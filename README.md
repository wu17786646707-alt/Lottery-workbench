# 双彩研究工作台 V12 — iPhone 一次上传正式发布包

**目标**：独立随机开奖的统计研究、可解释选号和可证伪回测；不是中奖预测保证。彩种：双色球、超级大乐透。

## 用户最关心的：新增走势图独立选号 C

打开 **三路选号** → 点击 **“只按走势图生成一注”**，或者 **“生成 A+B+C 三注”**。

- **A 数据研究员**：近期频率、遗漏、走势变化、组合形态综合评分。
- **B 经验老彩民**：模拟奇偶、分区、和值、跨度等常见经验型规则，并非采访真实彩民。
- **C 走势图独立选号**：观察近20期与此前20期的出现次数变化，加上时间衰减频率和组合筛选，独立生成一注。
- 点击每组 **“为什么选择这些号码”** 可逐球查看出现次数、均匀随机理论期望、遗漏、短窗与前窗差值；这些只是算法原因，不代表未来概率优势。

## 完成的功能（V11 审计问题修复）

- 数据：双色球33+16 / 大乐透35+12，5位与7位期号统一为7位；号码、日期、重复、冲突校验；冲突隔离；存储来源和验证状态；疑似断号提示。
- 历史：第三方源镜像回退、本仓库快照优先、浏览器打开后自动尝试同步、手动同步、CSV导入、历史搜索。
- 数据采集：附 `sync_history.py` 和 `.github/workflows/update-lottery-data.yml`，在 GitHub Actions 启用后计划北京时间每日09:09/23:09运行；官方端点不可用时不伪称独立核验。
- 图表：真实开奖号码走势图、全历史起点累积遗漏矩阵、八张统计小图、窗口敏感性对照。
- 策略：A/B/C 三路选号，共用同一 `pick()` 策略内核；逐球理由及可重复研究快照。
- 杀号：低频、高频、最长遗漏；排除原因、误杀核对、24次随机基准之外的独立固定随机杀号对照；规则修改后自动重新计算。
- 守号：手动球盘、保存、暂停、最近历史核对、删除。核对仅统计命中号码，不擅自计算真实奖金或奖级。
- 实盘研究：每期仅允许锁定一次；保存时间、号码、依据、策略版本、数据指纹及杀号规则；开奖后核对并生成简要复盘。
- 回测：严格按日期顺序滚动、每期只使用过去数据；A/B/C与24组固定随机种子均值对照；探索性z值/置信区间/符号随机化p值、保守多比较校正、三段稳定性地图。
- 数据安全：导入字段严格校验、转义展示、文件大小限制；IndexedDB优先，localStorage回退；统一 V12 完整备份（历史+守号+研究档案），自动尝试迁移 V5~V11 本机数据，支持老版 lottery-v5 全量备份与 V10 研究记录备份合并。
- 工程：拆分 `core.js` / `engine.js` / `app.js` / `styles.css`；无前端第三方依赖；CSP、版本化 PWA service worker；可离线回看已保存的数据；Node/Python 单元测试。

## iPhone：网页功能只需上传一次

1. **务必先打开现有 V11 的数据页，分别导出“完整备份”和“研究员锁定记录”**。原版把研究记录放在另一个本地键中，旧版的完整备份可能不包含研究锁定记录。
2. 在 iPhone “文件” App 中解压本 ZIP。
3. 打开 `https://github.com/wu17786646707-alt/Lottery-workbench/upload/main`。
4. 将以下 **10个根目录文件** 一次选择并上传，覆盖已有同名文件：

```
index.html
styles.css
core.js
engine.js
app.js
sw.js
manifest.webmanifest
icon.svg
sync_history.py
README.md
```

5. **点击 Commit changes**。等待 Pages 成功部署。打开 `https://wu17786646707-alt.github.io/Lottery-workbench/`，应显示 **V12**，旧版的开奖号与守号会尝试自动迁移；请先核对数量。
6. 如果页面仍显示旧版，首先正常刷新或关闭重开 Safari；不要直接清除网站数据，清理前务必确认已导出备份。

## 开启真正的定时后台更新（首次还需要一次工作流安装）

静态 GitHub Pages 本身不能定时运行 Python。ZIP 附带的 `.github/workflows/update-lottery-data.yml` 必须位于仓库的**同一相对路径**才能启动 GitHub Actions；直接把它上传到仓库根目录是无效的。

- 如果通过电脑或支持保留相对路径的 Git 工具上传整个 ZIP 内容，`.github/workflows/update-lottery-data.yml` 可以随其它文件一起正确提交。
- **仅用 iPhone Safari 的 GitHub “Upload files”** 往往无法保留隐藏子文件夹的相对路径。这种情况下先一次上传上述10个文件，即可运行前端和打开网页时的在线同步；然后在 GitHub 网页的仓库 `Add file → Create new file` 中，把**新文件名**填写为 `.github/workflows/update-lottery-data.yml`，粘贴随包 YAML 内容并 Commit（请勿上传成根目录的普通 YAML）。
- 后续进入仓库 `Actions`，在 **Update real lottery history (source-audited)** 中手动运行一次 `Run workflow`，检查是否创建 `data/history.json`。仓库 Actions 写入权限如受限，需要在设置中调整；工作流失败不能视为已自动更新。
- 网页优先读取 **GitHub raw 分支上的数据快照**（防止由 GITHUB_TOKEN 写入的快照未触发 Pages 分支重构建），其次读取 Pages 内的快照，最后回退第三方单源历史库。所有来源均有标签。

## 严格限制和不作出的保证

- 未在真实 iPhone Safari 中完成端到端测试；静态语法检查、Node 策略单元测试、Python 数据管道单元测试、模拟 DOM 交互烟雾测试均已完成。模拟开奖只出现在测试脚本里，绝不打包为正式历史开奖记录。
- 公开历史数据来源是第三方维护的仓库，官方 API 独立核验取决于第三方端点的实时可用性和 GitHub Actions 能否访问。**没有独立核验的数据必须显示为“单源/待核验”。**
- 本机研究“锁定”记录无法防止设备所有者修改文件、系统时间或浏览器数据，**不能当作第三方独立证明**。
- 窗口探索、策略权重选择、历史回测和统计显著性测试可能产生多重检验/过拟合；报告的 z、置信区间和 p 值是探索性参考，并非可靠的下一期中奖优势证明。
- 购彩要控制预算；彩票若独立公平随机，任何号码组合的理论中奖概率相同。
