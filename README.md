# 双彩研究工作台 V18.0 — 下一期选号决策与同预算复式（iPhone 统一部署）

## 本次完成的功能

此版本针对用户反馈“号码到底预测哪一期、复式对照为什么不能保存、近30期选号依据不透明”等实际问题；继承 V17.2.1 的真实开奖记录、走势图、形态先行、实盘复盘、杀号实验室、一等概率和数据恢复功能，不从零改写旧业务代码。

1. **下一期选号决策中心**（首页导航新入口）：明确显示「已开奖历史基准期」「预计未来研究目标期」「本机即时计算 / GitHub公开提前锁定的区别」。在已知目标开奖时点后、最新数据仍未同步时，停止生成当前期候选。
2. **具体单式和复式、逐球说明**：选择 A 数据、B 经验形态、C 走势研究员，指定60/120/300期参考窗口；每个球对照近30、120、300期出现次数、当前遗漏和研究员原始解释；主区与后区支持展开全部号码表。历史频率、遗漏只是描述，不声称特定号码下一期概率更大。
3. **真正可用的同预算复式**：双色球可选 **8+1 或 7+4**，两者均为28注，基本投注56元；大乐透可选 **7+2 或 5+7**，两者均为21注，基本投注42元。两类结构均覆盖对应研究员的单式。切换结构后必须重新生成，不偷偷叠加两组；预算不足则不能将方案送入保存页。大乐透的42元不含追加，若另行选择追加，成本会不同。
4. **保存、备份、历史核对完整兼容**：正式“复式选号”页面可生成、复制、保存8+1/7+4或7+2/5+7。存储 `safeCompound` 新增两种格式支持，原已保存旧格式不丢失，结算显示每组独立注数、金额、基准期号与目标日期。仍使用 IndexedDB `lottery_v12` 和 `lottery-workbench-v12` 完整 JSON 备份格式。
5. **近30期冷热方法严格走时回测**：对主区每次只使用此前30期，预测随后一期，显示较近500期与再往前500期两段高频／低频平均命中和等量随机理论均值。没有稳定样本外优势时，不提高冷热／遗漏权重，也不增加硬杀号。
6. **三位研究员仍各自研究，仅一组主复式**：没有根据一次开奖的输赢擅自修改选号权重或更换自动记录算法。新页面默认 A 数据视角，用户可选 B 或 C；在形态实验页默认 B 是一种研究偏好，不表示其数学概率更高。

**数学边界**：各组的具体单式开奖概率相同。同成本、同数量、不重复的复式，总一等奖概率相同。增加不同有效注数会按比例增加概率，也会按比例增加基本成本。没有统计方法能保证中一等奖。

## 发布方法（只需一次统一提交）

1. 在当前线上工作台进入「数据与备份 → 下载完整 JSON 备份」，保存至 iPhone「文件」；不要清除 Safari 网站数据。
2. 下载并解压 V18 ZIP；**仅上传 `01_只上传这21个文件到仓库根目录` 内的全部21个文件**，不要上传外层文件夹，也不要上传测试文件。
3. 在 `https://github.com/wu17786646707-alt/Lottery-workbench/upload/main` 选择 `main` 根目录并提交覆盖。
4. **严禁删除或覆盖** `history.json`、`research.json`、`health.json`、`official_latest.json`、`.github/workflows/update-lottery-data.yml`。上述数据与工作流文件不在这次上传文件夹中。
5. GitHub Pages 发布成功后，用 Safari 打开 `https://wu17786646707-alt.github.io/Lottery-workbench/?v=18.0`。
6. 打开“下一期选号决策”页面，检查双色球8+1/7+4与大乐透7+2/5+7，核对预算0时按钮禁用；选一组后跳转至“复式选号”并保存，再返回检查。同样验收首页开奖号码、走势图、历史开奖、复盘、去重概率页正常显示。

## 版本、数据与真实测试边界

- 打包部署仅改变静态网页和研究UI；**没有更改线上 GitHub 的实际开奖记录和公开提前锁定号码**。自动化 `automation_research.mjs` 不改核心策略和过去的预测战绩。
- 不保证节假日或停开的未来日期准确；显示“预计期号／预计日期”，以官方公告为准。
- 官方独立核验接口曾出现 HTTP403/567，所有单源数据必须仍标注核验不足；V18 没有宣称解决独立双源问题。
- 已运行 121 项纯算法断言、Chromium 手机宽度模拟点击：原首页真实读取链路（测试使用内存专用合成开奖记录）、走势图8张图、开奖列表、研究页面、4种复式选择、7+4/5+7正式保存、彩种切换、形态实验、复盘、概率页面，均通过；**模拟数据不会进入发布包**。
- 浏览器测试是 Chromium/390px 的合成数据环境，不等于真实 iPhone Safari 与现场网络验收。GitHub Actions 绿色运行不等于所有开奖已同步或完成独立核验。
- 此包本身不直接修改 GitHub 仓库；是否已上线必须以 GitHub 实际提交和 Pages 部署记录为准。
