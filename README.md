# 双彩研究工作台 V13.0 — 重号 / 连号 + 复式 + 赛季自动复盘

适用仓库：`wu17786646707-alt/Lottery-workbench`，主分支 `main`，免费 GitHub Pages，iPhone Safari。

> **定位**：基于真实历史开奖数据进行统计研究和可证伪的策略对照。公平、独立的随机开奖不能依靠历史走势可靠预测；本程序生成的是研究候选，不是中奖保证。复式增加包含的单式注数与成本，不能提高单注中奖概率。

## 一、V13 主要改动

1. **重号 / 连号**：走势页展示最近一期的重号数量、连号对数及 20/30/60/100 期的真实历史分布；A/B/C 三策略把这两个特征作为较低权重的组合参考。复式选球数较多，已对历史结构约束进行数量校正。
2. **三位研究员升级**：A 保留频率 / 遗漏综合评分；B 修复两球后区无法覆盖三区的结构奖励；C 综合 10、20、40 期走势变化。每注的逐球解释注明是否与最近一期重复、历史观察值和理论期望。不表示存在确定趋势。
3. **复式选号**：独立“复式选号”页可选 A/B/C/随机，对应双色球 **8 红 + 1 蓝，28 注，基本 56 元**；大乐透 **7 前 + 2 后，21 注，基本 42 元，若选择追加合计 63 元**。支持复制、导出卡片、保存守号、开奖后查看展开单式命中分布。
4. **复式滚动回测**：与正式生成使用同一 `makeCompound()` 策略代码；显示历史覆盖命中与同等选球数量的随机理论基准。不可把覆盖率误称实际中奖率、收益率。
5. **自动研究员档案**：未来的新公开提前锁定记录同时保留 A/B/C 单式、三种复式、逐球解释和重号 / 连号参数。旧记录不事后补造复式成绩。仅当目标开奖日的数据已收录才核对，不允许使用更晚期替代。
6. **后台时效健康状态**：自动生成 `health.json`，分别报告数据时效、独立核验状态与实盘复盘状态；API 失败或开奖结果仍落后时发 GitHub Actions 警告。绿色任务并不等于核验成功。
7. **开奖后重试机会增加**：升级工作流安排北京时间 22:26、23:26、次日 00:26、01:26、10:16 尝试运行（GitHub 定时任务可能延迟）。节假日 / 停开期间不会因为日期判断错误而虚构开奖。
8. **兼容旧版数据**：沿用 `lottery_v12` IndexedDB 本地库，新增的复式方案存入 `state.compounds`，在完整备份中一并保留。旧单式、守号和研究记录不会主动清空。

## 二、iPhone 必须按这个顺序升级

### 第 0 步：先备份

打开现有 V12.2 网站的“数据与备份”，点击**下载完整 JSON 备份**；在“研究战绩”另外**导出锁定记录**更保险。保存到 iPhone 文件 App。

### 第 1 步：一次上传 10 个网页/逻辑文件

打开压缩包里的 `01_上传到仓库根目录` 文件夹，选择其中 **10 个文件**，在下面的 GitHub 页面上传并替换原文件，最后 **Commit changes**：

https://github.com/wu17786646707-alt/Lottery-workbench/upload/main

10 个文件：`index.html`、`styles.css`、`core.js`、`engine.js`、`app.js`、`automation_research.mjs`、`health.json`、`sw.js`、`manifest.webmanifest`、`README.md`。

**非常重要**：绝对不要上传压缩包里的测试用历史 JSON 去覆盖仓库的 `history.json`，也不要覆盖 `research.json`！它们保存了你当前的真实历史数据和已经提前锁定的研究记录。本升级包的“01”文件夹**故意不包含**这两个文件。**不要把文件夹 `01_上传到仓库根目录` 本身套在仓库外层。**

保留仓库原有的 `sync_history.py`、`package.json`、`official_latest.json`、`icon.svg`，它们目前不需要改动。

### 第 2 步：更新已有自动工作流（这是 GitHub 网页上独立的一次编辑）

打开：

https://github.com/wu17786646707-alt/Lottery-workbench/edit/main/.github/workflows/update-lottery-data.yml

在 Safari 中打开 `02_替换已有自动工作流/工作流内容_复制粘贴.txt`，复制全文，完全替换 GitHub 编辑器里的原内容，点击 **Commit changes**。**不要新建第二个工作流**，否则可能重复定时运行。

> 技术边界：GitHub 手机上传界面不能保证把 `.github/workflows/` 隐藏目录连同结构直接上传，因此整个升级包虽然只需下载一次，GitHub 上需要“根目录批量上传 + 修改已有工作流”两次操作。若暂时不方便编辑工作流，前端仍可用，但后台不会新增频繁重试与 `health.json` 自动提交功能。

### 第 3 步：首次运行及验收

1. 打开 Actions： https://github.com/wu17786646707-alt/Lottery-workbench/actions/workflows/update-lottery-data.yml
2. 点击 **Run workflow** → 选择 `main` → **Run workflow**。
3. 等待任务结束；如果失败，点击红色运行记录查看 `synchronize` 下哪个步骤有问题。**不能只看 Pages 网站构建是否成功。**
4. 成功后回到仓库检查 `health.json` 是否出现新的 `generatedAt`；再查看 `research.json` 里后续新目标期的 `compoundPicks` 是否出现。已锁定的旧期不会事后补造它。
5. 打开网站： https://wu17786646707-alt.github.io/Lottery-workbench/?v=13.0
6. 确认标题 `V13.0`；进入“复式选号”，双色球生成 8+1，切大乐透生成 7+2；查看“走势与图表”里的重号和连号统计；打开“研究战绩”与“数据与备份”看后台健康状态。

**如果首页仍显示旧版本**：用 Safari 新标签页打开带 `?v=13.0` 的网址，刷新；先不要清空 Safari 网站数据，以免丢失本机守号。

## 三、关于可验证性

- **官方接口**：之前 GitHub Actions 日志出现福彩官方 HTTP 403、体彩官方 HTTP 567。V13 保留双源核验尝试和明确的健康警告，但**未保证官方接口一定能访问**。失败时仍标记单源/未独立核验，绝不冒充“官方双源验证完成”。
- **定时任务**：GitHub Actions 的定时执行有延迟，无法保证开奖后立刻同步；本版通过增加几个开奖后重试窗口改善及时性，并显示滞后告警。
- **提前记录**：新复式记录只能从 V13 后真实定时执行时开始积累，不对旧期开奖追溯补造。浏览器自动展示的候选不等于 GitHub 后台提前锁定记录。
- **开奖策略**：重号、连号、遗漏和短期频率变化可检验，却不能因历史回测好看就宣称未来中奖率提高。
- **复式金额**：以上是基本/追加的标称单票组合价格，不含倍数或额外组合，不代表你已经购彩。
