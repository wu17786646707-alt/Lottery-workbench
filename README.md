# 双彩研究工作台 V16.0 · 形态先行 + 单组复式

**面向 iPhone + 免费 GitHub Pages；不需要购买服务器。**

## 1. 产品决策：三位研究员研究，但只选择一组主复式

- A 数据研究员：20 / 60 / 120 / 300 期频率、遗漏、多窗口收缩；兼顾形态。
- B 模拟经验研究员：优先研究龙头凤尾、三区比例、奇偶、大小、和值跨度、重号与连号，**默认作为唯一主展示复式**。不是因为 B 被验证更准，而是因为用户希望优先验证“先形态再选号”的方法。
- C 走势图研究员：10 / 20 / 40 期相邻窗口变化，保留形态作为辅助约束。
- A/B/C 每位都有**各自单式 + 各自 8+1 / 7+2 复式研究方案**。新的“形态先行·一组复式”页面默认只展开 B 的复式；A/C 放在折叠的备选区。
- 切换主研究员只是**替换**主方案，不累加买三组；导出、复制、转入保存入口都只作用于用户选定的一组。
- 双色球 8 红 + 1 蓝：C(8,6)=28 注，基本投注 56 元；大乐透 7 前区 + 2 后区：C(7,5)=21 注，基本投注 42 元。大乐透可选的追加费用没有默认开启。复式包含研究员本人对应单式。
- 预算上限可以设为 0。预算低于单组复式成本时，不允许选择、复制或导出那组复式，不提示追加预算。**本工具不自动购票。**

## 2. 研究流程：先形态，再落号码

1. 检查最新历史数据快照，并显示来源的独立核验状态。不得使用模拟开奖替代真实数据。
2. **软杀号**：结合最近60期频率、当前遗漏做低优先级标注；默认不排除任何实际号码。向用户同时显示如果硬杀号，按公平随机模型至少误杀一个真正开奖号码的理论风险。另有独立的老版硬杀号实验室供用户验证。
3. 使用最长300期的历史记录构建主区**候选形态**：龙头（最小号码）、凤尾（最大号码）、三区比例、和值、跨度、奇偶、大小、重号、连号、邻号及三期斜连号。查看候选形态、观察区间及实际结果差异。采用软评分，不将极端形态彻底排除。
4. 在候选形态约束下，为 A/B/C 使用其不同的号码评分方式生成各自的主区单式。
5. 蓝球/后区独立生成；大乐透后区展示奇偶（1奇1偶或同奇偶）、大小及间距。**更常见的形态类别不代表其中某一组号码开出概率更大。**
6. 每位研究员再扩充为主区8/7码复式，保留该研究员的原单式，并按复式选球数校正形态偏差。
7. 使用相同策略实现的严格时间滚动回测及随机基准比较，更新未来提前锁定记录。**过往锁定记录不被改写**。

形态和杀号都是待检验的假设。对公平独立随机开奖的有效单式，没有经过验证的赔率优势、没有可承诺的头奖预测概率提升。提高覆盖注数会等比例增加头奖概率与投注成本。

## 4. iPhone 一次部署说明

1. 在旧版“数据与备份”下载完整备份，并将其保存到 iPhone 文件 App。
2. 在下载的 ZIP 里找到 `01_只上传此文件夹内的14个文件`。将**内部的 14 个文件**，而非整个文件夹或 ZIP，上传到现有 GitHub 仓库 `wu17786646707-alt/Lottery-workbench` 根目录，选择替换同名文件并点击 **Commit changes**。
3. **不要删除**仓库现有的 `icon.svg`、开奖数据和自动工作流，也不要将测试文件夹上传到根目录。
4. Pages 建立后打开 `https://wu17786646707-alt.github.io/Lottery-workbench/?v=16.0`。确认顶部 V16.0。iPhone 如继续显示旧版，尝试 Safari 刷新网站或删除旧主屏幕图标后重新添加（先确认已有完整备份）。
5. 打开“形态先行·一组复式”，先选双色球 → 生成研究 → 看到 A/B/C 三组单式、主复式 B（28注/56元），切换主研究员后主复式必须替换，备选两组不自动累加；把预算改到 0 或 42 元时双色球主方案应被阻止。
6. 切到大乐透 → 生成研究 → 看到单组7+2（21注/42元）、后区形态分析；预算如为 0，应该被阻止。选择有效方案后可转到原有“复式选号”页面手动保存，本机结果依然需要定期备份。
7. 核查“研究战绩”保留过去实盘档案；GitHub Actions 页面查看更新任务是否继续成功。新策略的公开研究记录必须出现在真实的下一次提前锁定之后，不能从旧记录补造。
