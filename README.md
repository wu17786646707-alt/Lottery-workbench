# 双彩研究工作台 V17.2 — 期次身份、旧号防误用、实盘页面完整检查版

这次升级重点是**消除“下一期研究号码”和“上一期历史号码”的混淆**，不是提高单注一等奖中奖概率，也不修改 A/B/C 的选号权重。

## 读号码先看四件事

- **历史依据（已开奖）**：最后一条已收录、用于统计的真实开奖结果，如双色球第 2026126 期。
- **研究目标（预计）**：计划用于下一次开奖的日期和期号，如双色球预计第 2026127 期。未来期号按顺序推算，遇停开、调整，以官方公告为准。
- **本机即时研究**：打开页面当下计算的候选号码，可能随历史更新或参考窗口变化而改变；**不是** GitHub 提前锁定档案。
- **GitHub 赛前锁定 / 真实开奖复盘**：自动任务开奖前写入仓库的不可回填号码；开奖后才结算。旧记录不会因为本次升级被重写。

## 具体修复

1. 首页增加贯穿页面的“历史依据 / 研究目标”双栏，并提供“下一期即时研究 / GitHub赛前锁定 / 已开奖复盘”三条快捷入口。
2. 单式选号、多窗口报告、形态先行、复式选号、复盘下拉框都显示目标日期与（推算）期号，避免把基准期号误认成预测期号。
3. 当前期开奖时间已过但真实开奖尚未同步时，暂停生成及锁定新的未来期候选，不把过期号码自动挂到下一期；复盘依然可以阅读。
4. 复式若与本机最新历史期号不一致，不会继续作为当前下一期候选显示；已保存的长期守号仍然保留。
5. 一等奖概率篮子标记生成时的历史基准期，跨期后禁止继续当作本期组合复制、导出或补齐；可以在列表长按复制留档，或清空重新生成。
6. 原先打开网页可能保留最长 24 小时的同步间隔；现在在重新打开网页或返回前台时，如果距上次同步超过约 20 分钟，则尝试同步，同时重新读取公开研究和后台健康数据。不会声称在后台持续每 20 分钟自动运行。GitHub Actions 自身的定时调度不变。
7. 修复“所有远程源失败，但页面仍提示同步完成”的状态误导；现在仅有本地旧数据时会明确告警。
8. 本机新锁定档案额外保留 `targetDate`；原有老档案与 V12～V17 数据结构向后兼容。
9. 统一版本标识 V17.2、模块引用和 PWA 缓存版本，降低 iPhone Safari 新旧 JS 混用风险。
10. 复盘页优先显示已结算记录，具体区分目标日期、已知基准期、期号（准确实际期号或未确认的推算期号）和结算状态。

## 兼容性和责任边界

- 保留既有 IndexedDB 数据库存储键 `lottery_v12` 和完整备份格式 `lottery-workbench-v12`，**不清除 Safari 网站数据**。
- 保留同一套 V17 策略 `research-v17.0-shape-first`；这次主要修复展示与时效逻辑，不能把改动当作预测能力已提高。
- 研究员以前的实盘锁定号码保持不变；自动任务不会在事后替换旧号码。后台继续使用相同代码策略，GitHub Actions 工作流不需要重新设置。
- 仍未解决部分官方直连接口 HTTP 403/567 的独立来源核验限制，远程数据可用不等于官方双源验证。
- 公平随机开奖中，相同数量不同有效组合的一等奖概率相同。没有任何形态分析能确保一等奖。

## iPhone 一次性部署

1. 进入原工作台 **数据与备份 → 下载完整 JSON 备份**，在 iPhone“文件”保存。不要清空 Safari 缓存。
2. 解压本 ZIP，**仅**进入 `01_上传这18个文件到仓库根目录`，选中其内部 18 个文件。
3. 访问 `https://github.com/wu17786646707-alt/Lottery-workbench/upload/main`，提交覆盖主目录的 18 个网页/程序文件。
4. **不要覆盖** `history.json`、`research.json`、`health.json`、`official_latest.json`；不要删除 `.github/workflows/update-lottery-data.yml`。
5. 等待 GitHub Pages 完成发布，再在 Safari 打开 `https://wu17786646707-alt.github.io/Lottery-workbench/?v=17.2`。
6. 验收：顶栏显示 V17.2；查看期次双栏、点击“下一期即时研究”、点击“赛前锁定”、点击“已开奖复盘”、切换彩种，检查三处目标期是否一致。
